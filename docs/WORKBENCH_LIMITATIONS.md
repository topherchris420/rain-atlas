# Explicit limits of this implementation

The architecture has been extended, not replaced. This delivery prioritizes
CI diagnosis, the complete offline review flow, numerical methods and a
reproducible synchronization study. The broader research-platform specification
is not declared complete merely because these pieces work.

| Area | Implemented | Still planned / not established |
|---|---|---|
| Observatory | Six views, recorded data, search/filter, downloads, offline composer | Live run monitoring; execution server; browser-rendered visual acceptance in this environment |
| Resonance | Eight primitives, typed skills, analytical and synthetic tests | Arbitrary physical cymatics, free-edge plate FEM, experimental sensor validation |
| Scientific workflow | Existing scripted roles, two methods, new seeded replication, computed verdicts, source reproduction | Generic adaptive follow-up scheduler, dynamic model-assisted execution, automatic resume |
| Proposals | Strict local JSON intake, provenance, operator gate, persistent declared budget | Live language-model adapters and model-quality evaluation |
| Skepticism | Nulls, perturbation/noise/phase-lag shifts, independent replicate intervals, multiplicity correction, exact-identity leakage rejection | General power analysis, posterior calibration, semantic leakage/selection-bias detection, general uncertainty propagation |
| Ledger | Artifact dependencies, source/lock snapshots, SQLite search, non-destructive torn-tail recovery | External authenticity, signed witnesses, automatic checkpoint resume, concurrent experiment-budget transactions |
| Integrations | Verified R.A.I.N. schema export, Luca shape recognition with quarantine | Live host acceptance, HTTP submission, authenticated Luca evidence promotion |
| Benchmarks | Executed classical spectral failure suite, counts/intervals, runtime and memory records | Population reliability, broad skill reliability scoring, Linux consistency, general error-detection sensitivity |
| Developer tooling | Locked source setup, lint/format, targeted scientific API types, Python and DOM tests | Standalone catalog-bearing wheel distribution, whole-core strict types |
| Security | Policy guard, portable artifacts, bounds, process cleanup, POSIX limits, Windows Job Objects | Secure hostile-code isolation, hardened containers, POSIX validation on a real Linux runner |

Budgets are checked before each run, charging the declared timeout against
remaining time. Registered proposal budgets survive a lab restart by counting
the ledger; concurrent engineers are not a transactional scheduler. Use one
engineer per experiment. Human approval is a local attestation, not a digital
signature or identity proof.

Sealed-run diagnostics are withheld and the input copy is removed. This does
not make arbitrary malicious generators incapable of encoding private inputs
in scientific output; only reviewed built-in generators belong in blinded
studies. Neither Python audit hooks nor resource limits are a secure sandbox.

A scientific method that fails its controls must not produce a supported
claim. An unresolved question remains a valid, preserved result.
