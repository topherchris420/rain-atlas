R.A.I.N. ATLAS (**R**ecursive **A**rchitecture of **I**ntelligent **N**exus) is a local-first research workbench. It runs computational experiments through versioned scientific skills, preregisters what would count as success or failure, records every run, challenge and verdict in a hash-chained evidence ledger, and lets you review that evidence offline. This is the first release.

## Install

Python 3.11 or 3.12. CPU only, with no model account, cloud service or GPU.

```sh
pip install rain-atlas          # or: uv tool install rain-atlas
atlas skills test               # runs every built-in skill's known-answer examples
atlas rain central --root atlas-data/rain-central
atlas ledger verify atlas-data/rain-central/ledger
```

The wheel and sdist are also attached to this release. To verify a download, run `sha256sum -c SHA256SUMS`. `sbom.cdx.json` is the CycloneDX 1.5 bill of materials for the runtime dependencies.

## What is in 0.1.0

- **Evidence ledger and observatory.** Preregistration, runs with engine and skill source snapshots, claims labelled OBSERVED, COMPUTED or INTERPRETED, independent challenges, and three-valued verdicts (supported, contradicted, unresolved). `atlas ledger verify` checks the hash chain, artifacts and record rules. The observatory is a self-contained, CSP-locked HTML review view.
- **31 executable scientific skills** across signal processing, dynamical systems, physics, neuroscience, statistics, astrodynamics and evaluation. Each comes with typed manifests, declared permissions and limits, and independently derived known answers. A bounded executor runs them.
- **Recorded experiments:** synchronization under noise (30 conditions: 5 supported, 10 unresolved, 15 contradicted), frequency recovery from noisy signals, a stress benchmark that documents where the methods fail, and held-out spectral calibration.
- **ORRERY orbital dynamics:** two-body, perturbed and N-body propagation, IAU-76/80 frames, DE421 ephemerides, orbit determination and covariance. It is validated against the analytic Kepler solution and NASA GMAT R2026a; that is code-to-code consistency, not physical validation.
- **BLACK GLASS:** offline, read-only static analysis of firmware you are authorized to examine. It covers inventory, service and dependency graphs, declared network surfaces, signature checks against operator-supplied trust anchors, and release diffs.
- **ATLAS Physical Scientist:** a simulation-only loop of prediction, contradiction and revision for competing resonance models.
- **Unified R.A.I.N. modules:** scientific memory, observability tracing, mission control with approval gates, protocol compilation, a simulation twin, local inference providers, a versioned knowledge store and a research browser adapter.
  - `atlas rain slice` runs one preregistered mission through all of them.
  - `atlas rain central` runs the central experiment.

## The central experiment, honestly

Does persistent scientific memory make a research system more efficient without making it wrong, even when the world changes? Protocol v2 has 150 programs per regime, stationary and shifting worlds, and Bonferroni-adjusted paired bootstrap intervals:

- Memory that must be confirmed by fresh evidence saves **26.9 %** of experiments (interval 24.3–29.5 %). The preregistered "at least 25 %" claim is therefore **unresolved**, not supported.
- That verified memory adds **no detectable false conclusions** after the world changes (+0.5 pp, interval −0.6 to +1.9).
- Memory that is trusted blindly reaches a false conclusion in **91 %** of missions after a change.
- The advantage of maximum-disagreement selection over a fixed sweep is an **ordering effect**: a fixed high-to-low design matches it on every mission.

An earlier protocol reported a 68 % saving that its own design guaranteed. It remains reproducible (`--protocol v1`) and is documented in [CENTRAL_EXPERIMENT.md](https://github.com/topherchris420/rain-atlas/blob/v0.1.0/docs/CENTRAL_EXPERIMENT.md).

## Validation

- **Full suite:** 674 tests passed, including the slow acceptance tests; 2 platform-specific skips.
- **Hosted CI:** every job passes on Ubuntu 24.04 and Windows Server 2022 with Python 3.11 and 3.12.
- **Packaging:** the wheel is installed into a clean environment and its CLI is run outside the source tree on both systems.
- **Reproducibility:** the recorded central-experiment output reproduces exactly on all four combinations.

## Known limitations

- The skill executor enforces declared permissions and resource bounds, but it is **not a hardened sandbox** for hostile code.
- The built-in research roles are scripted policies. No language model participates in the demonstrations. Local Ollama and llama.cpp providers are optional.
- All recorded experiments are synthetic. A verified ledger proves internal consistency, not authorship, real-world validity or scientific truth.
- The BLACK GLASS demonstration uses synthetic firmware. No official vendor executable has been analysed.
- The memory store rewrites its snapshot on each commit, which suits stores of thousands of memories, not millions.
- macOS has not been tested.
